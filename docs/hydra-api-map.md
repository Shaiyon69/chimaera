# Hydra API map (derived from client code only)

Source: static reading of this repo. Nothing here was verified against a live server. Types below are what the client **consumes**; extra server fields are ignored. Paths are relative to `MAIN_VITE_API_URL`.

Legend: **Auth** = `needsAuth` (client default is `true`; `F` means the call passes `needsAuth:false`). **Sub** = `needsSubscription:true` (client pre-checks, see section 1). `R:` = renderer, `BP:` = Big Picture (`src/big-picture/src`), unprefixed = `src/main`. Renderer/BP calls go through `window.electron.hydraApi.*` -> IPC `hydraApiCall` (`events/misc/hydra-api-call.ts`) -> `HydraApi`, so they share the same auth/refresh behaviour.

## 1. Transport, headers, auth mechanics (`services/hydra-api.ts`)

| Item                | Behaviour                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Base URL            | `import.meta.env.MAIN_VITE_API_URL` (axios instance, `hydra-api.ts:200`). Also used raw in `services/game-executables.ts:15` (`GET {API_URL}/catalogue/steam/executables`, plain axios, **no Authorization header**).                                                                                                                                                                                                                                                                          |
| Other env URLs      | `MAIN_VITE_AUTH_URL` (hosted sign-in web app, section 3), `MAIN_VITE_CHECKOUT_URL` (hosted checkout/cloud web app; also `/cloud` iframe via `getCloudIframeUrl`), `MAIN_VITE_EXTERNAL_RESOURCES_URL` / `RENDERER_VITE_EXTERNAL_RESOURCES_URL` (`app.tsx:366` loads `/bundle.js?t=` script), `MAIN_VITE_LAUNCHER_SUBDOMAIN` (loads UI from `https://release-v{ver}.{subdomain}`, falls back to local file), `MAIN_VITE_ANALYTICS_API_URL` (declared in `vite-env.d.ts`, no use found in `src`). |
| Headers             | `User-Agent: Hydra Launcher v{appVersion}`; `Authorization: Bearer {accessToken}` on **every** request through the wrapper, even when `needsAuth:false` (token is `""` when logged out, so server must tolerate `Bearer ` empty on public routes). GET only: `Hydra-If-Modified-Since: <UTC string>` (option exists, no caller uses it) and `If-None-Match: <etag>` (used by `/games/:shop/:id/achievements`).                                                                                 |
| Content             | JSON bodies via axios defaults. Presigned uploads are `axios.put` to external (S3-like) URLs, not the API.                                                                                                                                                                                                                                                                                                                                                                                     |
| `needsAuth`         | If not `false`: throws `UserNotLoggedInError` locally when no token; then if `expirationTimestamp < now` calls `refreshToken()` first. Expiration timestamp = `now + expiresIn*1000 - 5min`.                                                                                                                                                                                                                                                                                                   |
| `needsSubscription` | If no active subscription locally, client calls `GET /profile/me` to refresh, then throws `SubscriptionRequiredError` locally if `subscription.expiresAt` is not in the future. Server is not asked to enforce but should (cloud save, artwork sync, etc.).                                                                                                                                                                                                                                    |
| Subscription state  | From `UserDetails.subscription` (`{id,status,plan:{id,name},expiresAt,paymentMethod:"pix"\|"paypal"}`); `active = new Date(expiresAt) > now`. Cached in LevelDB `user`.                                                                                                                                                                                                                                                                                                                        |
| 401 handling        | Any 401 from the API (after the call) wipes in-memory auth + LevelDB `auth`/`user`, stops achievement/souvenir workers, closes realtime socket, emits `on-signout`, rethrows. Failed refresh (any error, only 401 triggers wipe) goes the same path. So: **return 401 only for bad/expired token**, never for "forbidden".                                                                                                                                                                     |
| Refresh             | `POST /auth/refresh` `{refreshToken}` -> `{accessToken, expiresIn(seconds)}`. Called with the raw axios instance (no bearer). Refresh token is not rotated by the client (response `refreshToken` ignored).                                                                                                                                                                                                                                                                                    |
| `validateStatus`    | Callers can whitelist statuses: 404 for artwork, 304 for achievements, `[201,400,404,429]` for souvenir report (via `postResponse`). Renderer `acceptedStatuses` also excludes 401 always.                                                                                                                                                                                                                                                                                                     |
| Errors to renderer  | `hydraApiCall` rethrows `Error(response.data.message)` if string else `error.message` else `"hydra-api-call-failed"`. **Error body convention: `{ "message": "<code-or-text>" }`** (some also `errorCode`/`code`/`reason`, see cloud save / souvenir). Network errors become `Error("Request failed with {code} {message}")`.                                                                                                                                                                  |
| Retries             | No generic retry/backoff in `HydraApi`. Retries are feature-local (cloud-save commit, souvenir worker, steam sync, realtime socket).                                                                                                                                                                                                                                                                                                                                                           |
| Logging             | Request/response bodies are logged (sanitised). No effect on contract.                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Realtime            | WebSocket (section 13), not SSE despite class name `SSEClient`.                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Other transports    | None. No axios elsewhere targets the API except `game-executables.ts`.                                                                                                                                                                                                                                                                                                                                                                                                                         |

## 3. Auth flow

1. **Sign-in UI is a hosted web app**, not an API call. Client opens an Electron modal `BrowserWindow` (Linux: separate handler `openLinuxAuthWindow`) at `{MAIN_VITE_AUTH_URL}{page}?lng={i18n}` (`window-manager.ts:661`). Pages (`AuthPage`): `/` sign-in, `/update-email`, `/update-password` (these two also get `&token={fresh accessToken}` from a forced `refreshToken()`).
2. The auth web app finishes by **navigating the window to** `hydralauncher://auth?payload=<base64(JSON)>` (intercepted in `will-navigate`, `window-manager.ts:638`; the window closes and `HydraApi.handleExternalAuth(url)` runs). Payload JSON: `{accessToken, refreshToken, expiresIn(seconds), workwondersJwt}`. `atob` + `JSON.parse`, so plain base64 (not url-safe base64url) of UTF-8 JSON, URL-encoded if needed.
3. On receipt: clears remote ids on local games, stores `Auth{accessToken,refreshToken,tokenExpirationTimestamp,workwondersJwt}` in LevelDB, calls `GET /profile/me`, updates subscription, starts souvenir worker, Steam startup sync, emits `on-signin`, uploads local library (`POST /profile/games/batch` then merge), connects realtime WS, syncs download sources.
4. `hydralauncher://update-account` (from the auth web app after email/password change) -> `on-account-updated` (refetch `/profile/me`).
5. **Refresh**: lazily before any authed call when expired (section 1). No proactive timer.
6. **Sign-out** (`events/auth/sign-out.ts`): closes WS, deletes local auth/user/games/downloads, `POST /auth/logout` (fire-and-forget, errors ignored; sent twice: once in `handleSignOut` with `needsAuth:false`, once plain). Body `{}` / none. Any 2xx or failure is fine.
7. **Steam OAuth (account linking, not login)**: renderer `startSteamOAuth(lng)` -> `GET /profile/oauth/steam/start?return_to=hydralauncher://steam-connected&lng=` (auth) -> `{authorizationUrl}`; client opens that URL in an OpenID window; server must redirect to `hydralauncher://steam-connected` on success (error variant: deep link carries `?error=` or `?oauth_error=`, or the OpenID page body is JSON `{message}` containing `already-linked`; codes `already-linked` | `generic`). Disconnect: `DELETE /profile/oauth/steam?deleteImportedData=true|false`. Server error `{message}` is surfaced to UI.
8. **Checkout/payments**: `POST /auth/payment {refreshToken}` -> `{accessToken}` (short-lived "payment token"); client opens `{MAIN_VITE_CHECKOUT_URL}{path}?token=&recipientId=` in the system browser. Allowed paths: `/`, `/gift`, `/gifts/{8 alnum}`. Payment itself is entirely in the hosted checkout app. After purchase the client only learns via `GET /profile/me` (`subscription`).
9. `workwondersJwt`: opaque string stored with auth and in `UserDetails`; passed to the third-party `workwonders-sdk` in the renderer (`app.tsx`, BP `use-user-details.hook.ts:29`). Not sent to Hydra API. Can be `""`.

## 13. Realtime WebSocket (`services/sse/websocket-client.ts`)

1. `POST /auth/realtime` -> `{token, url, expiresIn?}` (`url` required, `ws(s)://`; expiry read from JWT `exp` if the token is a JWT, else `expiresIn`; token cached with 30 s skew).
2. Connect with header `Authorization: Bearer {token}`, handshake timeout 15 s, client sends WS **ping** every 30 s; replies to server pings.
3. Messages are JSON envelopes `{v:1, eventId:string, publishedAt:number|ISO-string, event, payload}`; invalid ones are dropped, duplicate `eventId` (last 1000) ignored. Events:
   - `friendRequest` `{invalidate:"friendRequests", senderId?}` -> client refetches `GET /profile/friend-requests` and `GET /users/:senderId`.
   - `friendGameSession` `{objectId, shop, friendId}` -> `GET /users/:friendId?shop=`.
   - `friendPresence` `{friendId, isOnline, version:int>=1}` (monotonic per friend).
   - `notification` `{invalidate:"notifications"}` -> refetch `/profile/notifications/count`.
4. Reconnect: full-jitter backoff 1 s to 30 s; honours HTTP `Retry-After` on the upgrade response; close codes `1012` (service restart) and `1013` (try later) with optional close-reason JSON `{retryAfterMs|retryAfterSeconds}`. On every reconnect client resyncs friend requests + notification count via REST.
5. Closed on sign-out/401.

## 15. Suggested minimal viable backend (in order)

1. **Env/hosting**: `MAIN_VITE_API_URL`, `MAIN_VITE_AUTH_URL` (a tiny sign-in page that ends with `location = "hydralauncher://auth?payload=" + btoa(JSON.stringify({accessToken,refreshToken,expiresIn,workwondersJwt:""}))`), `MAIN_VITE_CHECKOUT_URL` (can be a stub).
2. **Boot**: `POST /auth/refresh`, `GET /profile/me`, `POST /auth/logout`, `POST /auth/realtime` (can return `{token:"x", url:"wss://..."}`; failure only logs, app continues).
3. **Public catalogue (no auth)**: `GET /features` (`[]` ok), `GET /catalogue/featured`, `/catalogue/hot|weekly|achievements`, `POST /catalogue/search`, `GET /catalogue/search/suggestions`, `GET /catalogue/steam/{genres,tags,developers,publishers}`, `GET /catalogue/steam/executables` (`{}` ok but client retries every 30 s on empty), `GET /games/:shop/:id/assets`, `/stats`, `/download-sources`, `/protondb`, `/how-long-to-beat`, `/reviews` (empty list), `GET /catalogue/:shop/:id/similar`.
4. **Download sources**: `POST /download-sources`, `POST /download-sources/sync`, `POST /download-sources/changes`, `POST /hosters/availability`, `POST /games/:shop/:id/download`.
5. **Library**: `GET /profile/games(+/hidden)`, `POST /profile/games`, `POST /profile/games/batch`, `PUT` playtime/favorite/pin/hide endpoints, collections, `PUT /profile/games/achievements`, `GET /games/:shop/:id/achievements`.
6. **Social** (friends, notifications, blocks, users/:id, badges), then **cloud save v2**, **artwork**, **souvenirs**, **integrations**, **launchbox `/games/shop-details`**, **payments/subscription** last.

Note: many mutating calls use `.catch(()=>{})`, so returning 404/501 for unimplemented ones is safe, but never 401 (forces sign-out).
